# Pointed brand guide

## Foundation

**Name:** Pointed

**Descriptor:** Pointing poker for Linear

**Positioning:** The pointing room that starts and ends in Linear.

Pointed helps a product manager bring Linear issues into one ordered room,
collect private estimates from the team, and write the result back to Linear.
It is a focused workflow tool, not a general Agile suite or a virtual casino.

## Audience

The primary user is the product manager or facilitator preparing and running a
grooming session. Developers are participants who need the issue context and a
fast, obvious way to vote from a computer or phone.

## Product promise

Bring in the issues. Point them together. Keep Linear current.

The promise must be supported by the product itself:

- import the real Linear issue queue
- let each teammate inspect the issue at their own pace
- keep votes private until reveal
- suggest the rounded result
- write the selected estimate back to Linear

## Voice

Pointed sounds like a focused product manager: calm, direct, and specific.

### Use

- short sentences and concrete verbs
- Linear's own nouns: issue, cycle, estimate, team, project
- exact state: “Waiting for two votes” or “Estimate saved to Linear”
- “pointing session” inside the product
- “pointing poker” when naming the category

### Avoid

- productivity hype: supercharge, unlock, transform, seamless
- vague momentum language: keep the team moving, move faster together
- anti-competitor jokes or references to Jira
- casino language, card suits, chips, tables, or bets
- anthropomorphizing the product
- calling an issue “ready” unless that state comes from Linear

## Core copy

### Homepage

**Point Linear issues with your team.**

Build the queue from Linear, share the room, and write each estimate back.

### Compact description

Open-source pointing poker for Linear.

### Longer description

Pointed imports an ordered issue queue from Linear, gives the team one place
to review and vote, and writes the final estimate back.

## Visual system

The mark shows three independent voters around one final point. It should
remain flat, single-color, and recognizable between 16px and 48px.

| Role | Value |
| --- | --- |
| Indigo | `#5e6ad2` |
| Near black | `#0b0d12` |
| Off white | `#f7f7f5` |
| Stone | `#6b7280` |
| Mist | `#a1a6b3` |

Use the indigo mark on light or dark neutral backgrounds. The one-color version
may use the current text color. Do not add a containing tile, gradient, glow,
shadow, poker-chip rim, or arrow.

Use the product's system sans-serif stack. The wordmark is set plainly rather
than treated as an ornamental logo. Its recognition comes from the name, mark,
spacing, and consistent product experience.

## Naming and discovery

Use **Pointed** in navigation, OAuth, page titles, and screenshots. Keep the
repository URL stable. Use “planning poker” only in metadata, README context,
and other discovery surfaces because it remains the category's common search
term.
